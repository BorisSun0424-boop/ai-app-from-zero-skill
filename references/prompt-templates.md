# 提示词模板

将方括号替换成实际信息。每次只在对应阶段使用一个模板。

## 资料结构

```text
把我后续开发[产品名]的资料存在[产品主文件夹]。要求：把我每一版和你对齐的需求存进[需求文档路径]，产品的代码和资产存进[代码文档路径]，产品的每个版本的宣传资料及后续发布资料放进[营销文档路径]。
```

## 需求澄清

```text
请你辅助我开发[产品名]。它想帮助[目标用户]在[使用场景]完成[核心任务]。在开发之前，先和我讨论并确定好产品需求。

请一次只问我一个最重要的问题。最后整理出：目标用户、核心任务、第一版必须做的功能、第一版暂不做的功能、数据是否只保存在本地，以及我需要确认的决定。没有得到我的确认前，不要开始设计或写代码。
```

## 页面结构与交互

```text
下面进入页面结构和交互设计阶段。请基于已确认需求，先给我页面结构方案：列出每个页面的目的、用户能完成的操作、关键状态，以及页面之间的跳转。先不要写代码或制作视觉稿；等我确认页面结构后再进行下一步。
```

## PRD

```text
请把刚才已经确认的内容整理成 PRD 文档，并保存在[需求文档路径]，作为后续开发依据。PRD 必须保留：产品目标、目标用户、核心使用场景、第一版范围、暂不做的内容、页面结构、关键交互、数据存储方式、验收标准和待确认问题。请在保存后告诉我文件路径，并等我确认后再进入开发。
```

## 开发计划与实施

```text
请根据[PRD 文件路径]生成一份开发计划。每个阶段写清：目标、涉及的页面或功能、完成后的可见结果、要运行的测试和验收方式。

在我确认计划后开始开发。每完成一个阶段，都要添加并运行对应的有效测试；测试失败就先定位并修复，通过以后再进入下个阶段。不得通过删除测试、跳过测试或降低验收标准让测试通过。全部完成后，运行所有测试，并告诉我如何打开 App 进行实际体验验收。
```

## 问题修复与迭代

```text
我在[页面或场景]发现这个问题：[问题描述]。

请先复述你理解的问题，并说明预计会影响哪些页面、数据或测试。得到我确认后再修改。修改后请复现原问题、运行相关测试和完整测试，并说明我应该怎样手动验收。不要顺带改动未提及的功能或视觉。
```

## 仅美化外观

```text
请只调整[页面/组件]的视觉外观，使它更符合[风格描述]。保留现有功能、交互、文案、数据结构和页面流程。先给出视觉调整方案，等我确认后再修改；完成后运行现有测试，并告诉我需要检查哪些视觉状态。
```

## Git 存档

```text
请检查[代码文档路径]中的项目是否已安装并配置 Git。若没有，请告诉我需要完成的最少步骤；若可以初始化，请先说明将要执行的 Git 操作和会提交的文件。得到我确认后，初始化仓库并为当前已经验收的版本创建一次清晰的提交。完成后告诉我提交摘要和当前工作区状态。
```
